# Technical feasibility

Research date: 2026-11-25. The [test plan](TEST_PLAN.md) defines the runtime evidence required before claiming compatibility.

| Evidence label | Meaning |
| --- | --- |
| Locally verified | Observed on this workstation or in artifacts generated by its installed binary |
| Documented | Described by the vendor or visible in its public source |
| Inference | Conclusion drawn from the evidence |
| Open | Requires a runtime test or a product decision |

## Executive finding

An independent Windows companion and VS Code dashboard are feasible using documented platform APIs. Genuine Codex **account** quota has a documented read path through a separately launched Codex App Server using Codex-managed sign-in. Activity for an existing VS Code session has a plausible opt-in hook path. The installed OpenAI extension uses private process stdio for its own App Server, and research found no supported passive subscription to that connection. Quota and activity can succeed or fail independently. [Electron window APIs](https://www.electronjs.org/docs/latest/api/browser-window) · [VS Code extension host](https://code.visualstudio.com/api/advanced-topics/extension-host) · [Codex App Server](https://learn.chatgpt.com/docs/app-server) · [Codex hooks](https://learn.chatgpt.com/docs/hooks)

## Codex integration paths

| Surface | Evidence | Pawmetry decision |
| --- | --- | --- |
| Separate, Pawmetry-launched App Server for quota | Documented `account/rateLimits/read` returns ChatGPT account usage. `account/rateLimits/updated` is a connection notification. Responses can provide multiple buckets, optional windows, used percentages and reset timestamps | Preferred quota experiment. Use Codex-managed sign-in, stdio and a quota-only RPC allowlist. Compare with the official usage UI on a known matching account and workspace. Treat missing or ambiguous buckets independently |
| Pawmetry-owned Codex thread and turn | Documented `thread/start` and `turn/start` give the owning client turn events, tool/item events, approval requests and final status, including `completed`, `failed` and `interrupted`. Thread status can indicate pending approval | Feasible for a product that runs its own agent. Outside the MVP because it shifts ownership and streams content. The exact-name notification opt-out list does not guarantee a metadata-only stream |
| Existing OpenAI extension session using default transport | Installed bundle uses its own stdio. No public extension event API, listener or documented observer path for that connection was identified | A second App Server may report the same account quota if it resolves the same identity and workspace. Its events establish nothing about the IDE-owned turn |
| Existing external session with its own hooks | Codex documents lifecycle hooks, user or trusted-project configuration, and trust review for non-managed hooks. Supported events vary with installed runtime | Preferred activity experiment in a disposable trusted workspace, with explicit consent. Test fresh, resumed and already-open sessions separately. Record reload or restart prerequisites |
| Explicitly shared App Server | OpenAI documents stdio, Unix sockets, a remote TUI client and an experimental unsupported TCP WebSocket transport. The installed CLI lists daemon and proxy commands | A deliberately shared server is a separate deployment model. Available transports do not confer a read-only role or establish that the stock Windows IDE is on that server. Exclude from MVP |
| Stored thread and local session metadata | `thread/read` reads stored metadata without subscribing. `thread/loaded/list` reports the connected server's in-memory threads. `thread/resume` loads or resumes a session in the connected server even with `excludeTurns` | Forego history RPCs in the quota client. A stored thread ID or transcript cannot establish live ownership, pending approval or terminal outcome in another process |

### Quota semantics

Read `rateLimitsByLimitId` when present and interpret the legacy `rateLimits` view according to the adapter's known bucket mapping. Avoid double-counting overlapping views. Reject an out-of-range `usedPercent` and calculate remaining as `100 − usedPercent` from a valid value. Use the supplied window length and Unix-second reset timestamp when present. Treat sparse update notifications as partial evidence from that connection and refresh with the read RPC when their scope or freshness is uncertain. Account limits can reflect activity across clients and, depending on plan, across products. API-key session token counts, context occupancy and reset-credit inventory cannot establish a ChatGPT allowance. December changes announced by OpenAI introduce additional plan variability, so verify the current response and avoid hard-coding five-hour and weekly windows. At reset time, request a refresh and wait for new evidence before showing recharging. [App Server rate-limit fields](https://learn.chatgpt.com/docs/app-server) · [Codex plans and shared allowances](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) · [Announced usage transition](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits)

### Hook semantics

Start with the smallest usable event set. A supported `PreToolUse` demonstrates tool work and a supported `Interrupt` demonstrates main-turn interruption. `PermissionRequest` shows an approval request is being considered and can run before other hooks decide whether the user sees it. Leave waiting unknown until the tested source establishes an unresolved approval. `UserPromptSubmit`, `PreModelRequest` and `PostModelRequest` are additional candidates whose availability, data exposure and meaning must be verified. `Stop` signals that the agent is finishing a response, so it does not independently prove success. `SessionEnd` can be delayed and is unsuitable as an immediate disconnect signal. Hooks have no documented quota feed for this IDE. The experimental MCP status line that can expose quota is for the CLI terminal footer. [Codex lifecycle and payloads](https://learn.chatgpt.com/docs/hooks) · [CLI status line](https://learn.chatgpt.com/docs/developer-commands) · [OpenAI custom status-line sample](https://github.com/openai/codex/blob/main/codex-rs/skills/src/assets/samples/create-statusline/SKILL.md)

Hook envelopes may include prompts, tool arguments and results, directories, transcript paths and assistant text. A bridge must discard those fields at ingress and emit only fixed activity metadata. Selective `mcp_tool` mapping is worth comparing where a hook event supports it, subject to transport, side effects and configuration review. If an event cannot be handled within the privacy boundary, keep that state unknown. [Hook handler and payload reference](https://learn.chatgpt.com/docs/hooks)

### Local metadata

Public Codex source shows rollout JSONL with thread metadata and event records, including optional quota snapshots alongside token-count events. Community tools demonstrate sampling those records. Formats, timing, coverage and account/workspace attribution can change. Writes can be buffered, incomplete, rotated or replayed, and idle clients provide no fresh quota. The same files can contain prompts and responses, and modification time alone does not identify agent activity. Transcript, log and private state parsing are outside the proposed integration. [Codex rollout recorder](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/recorder.rs) · [OpenAI rollout test fixtures](https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/common/rollout.rs) · [Agent Pets privacy notes](https://github.com/ifBars/agent-pets/blob/main/PRIVACY.md)

## Minimized, closed and remote

**Documented platform capability.** An independently launched Electron window has its own lifecycle. VS Code desktop has a local Node extension host that can run the Pawmetry UI extension. An App Server quota reader owned by the desktop main process can run independently while that desktop process and provider connectivity remain available. [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window) · [VS Code extension host](https://code.visualstudio.com/api/advanced-topics/extension-host)

**Inference to test.** Minimizing VS Code should leave live provider processes and active hook delivery running while Windows is awake. Minimizing, hiding a sidebar, reloading, closing the host, Windows sleep and a provider running in WSL or remotely are separate cases. Activity becomes unknown after expiry or a known disconnect. The desktop can remain visible after editor exit and may still refresh quota independently. Fullscreen apps, secure desktop, virtual desktops, mixed DPI and display hotplug require Windows checks. Keep Electron renderer throttling enabled and run data refresh in desktop main. [Electron renderer visibility](https://www.electronjs.org/docs/latest/api/browser-window#page-visibility) · [VS Code remote development](https://code.visualstudio.com/api/advanced-topics/remote-extensions)

## Release gates

| Risk | Mitigation and open decision |
| --- | --- |
| Wrong account, workspace or bucket | Compare against the official UI and deliberately test ambiguous scope. Keep usage and activity independent and show unknown when scope is uncertain |
| Concurrent sources and quota attribution | Centralize refresh by verified provider, authentication mode, account, quota scope and bucket. Treat local projects, client instances, conversations and turns as separate identities. Keep activity unknown when a specific source is unobservable. [Concurrency design](ARCHITECTURE.md#multiple-windows-projects-and-sessions) |
| Version or plan drift | Record binary, extension, OS and sign-in mode per capability. Re-run the relevant smoke tests on changes |
| Native executable discovery | A bundled Codex executable may be absent from the user's shell PATH, and extension upgrades can change its path. Future onboarding should validate the executable and offer an explicit path when a trusted installation cannot be identified. [Observed discovery issue](QUOTA_PROBE_REPORT.md#limits-and-remaining-risks) |
| Hook exposure, availability or latency | Require consent, trust and measured event delivery. Exclude hooks that exceed the privacy boundary |
| IPC access across users and sessions | Verify Windows pipe permissions and remote rejection before using real data. See [security design](SECURITY.md) |
| Overlay behavior and packaging | Test standard-user installs, mixed-DPI geometry, transparency and tray recovery. Decide signing and SmartScreen handling before public distribution. [Electron code signing](https://www.electronjs.org/docs/latest/tutorial/code-signing) |
| Third-party rights | Clear the name and choose the project license before public release. Preserve original asset provenance. See [third-party notices](THIRD_PARTY_NOTICES.md) |
