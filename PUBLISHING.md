# Pawmetry release checklist

Use this checklist for a public Windows x64 preview. Build locally and publish manually using GitHub Free and the VS Code Marketplace publisher dashboard. Keep release binaries as GitHub Release assets. This workflow needs no paid hosting, CI, Azure subscription, domain, signing certificate, or separate Pawmetry API bill. Use the existing Codex sign-in for quota testing. [GitHub Free](https://github.com/pricing) · [Release asset limits](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases#storage-and-bandwidth-quotas) · [Marketplace publication](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#publish-an-extension)

## Before publishing

1. **Confirm the scope.** The v0.1.5 preview installs from a single Windows x64 VSIX and ships live quota and Cat. Native prompt activity remains a separate development milestone. [Native activity test](MANUAL_TESTS.md#native-codex-activity)
2. **Run the clean installation check.** In local Windows 11 x64 VS Code, install the checked VSIX, click **Start Pawmetry**, compare the quota with Codex, hide and restore the pet, exit, and uninstall. A solo maintainer can run these checks on their current account and record a genuine standard-user run separately when a suitable account is available. Record Windows or endpoint-policy blocks with protections enabled. The bundled executable is unsigned. Its checksum identifies the artifact and cannot guarantee Windows will allow it to run. [Acceptance checks](MANUAL_TESTS.md#single-install-preview) · [Microsoft SmartScreen](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation)
3. **Confirm the public identity and artwork terms.** MIT and the copyright attribution are approved. The maintainer confirmed that Cat was made using only ChatGPT and approved redistribution of Cat and the logo as part of Pawmetry. Record the official repository URL and a private security contact. Review the Pawmetry name and trademark search results in relevant markets. [MIT license](LICENSE) · [Artwork terms](assets/mascots/cat/DISTRIBUTION.md) · [IPOPHL search tools](https://www.ipophil.gov.ph/trademark/trademark-online-tools/)
4. **Use the verified release package.** The publisher account is set up. The local public candidate is `renzangelo.pawmetry` v0.1.5 in `dist/pawmetry-8a7iSS`, with the SHA-256 recorded alongside it. The maintainer reported successful install and launch from VS Code on a standard Windows account with no warning. Marketplace upload still needs approval. [Acceptance checks](MANUAL_TESTS.md#single-install-preview)

The maintainer owns the `renzangelo` Marketplace publisher and approved a no-cost unsigned preview conditional on passing the final standard-user acceptance test with Windows security protections enabled. Microsoft signs the Marketplace extension separately from Windows code signing for the bundled executable. SignPath Foundation is a possible free signing route for later releases. Eligibility is pending and includes an existing release and open-source component requirements. [VS Code runtime security](https://code.visualstudio.com/docs/configure/extensions/extension-runtime-security) · [Windows SmartScreen](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation) · [SignPath Foundation terms](https://signpath.org/terms.html)

## After explicit release approval

The current release checkout provides `npm.cmd run package:public-preview` for the final build. It requires matching versions, a permanent publisher, public repository and issue tracker URLs, the approved source license, and confirmed Cat distribution terms. It creates and audits a local VSIX without uploading it.

5. **Prepare the existing repository and a GitHub prerelease.** Use `RenzAngelo/pawmetry`. Review existing Git history, hosted Actions, and the planned release commit before changing visibility. Use an explicit, audited branch or pull request and avoid pushing all local refs. After approval, draft a GitHub prerelease with the exact tested VSIX, `SHA256SUMS.txt`, installation steps, and unsigned-app limitation. [GitHub release steps](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases)
6. **Upload the tested VSIX to the Marketplace.** Use the publisher dashboard's VSIX upload option and the Windows x64 pre-release package. Check that the public listing installs on Windows and that the companion launches from VS Code. The current package size has been verified for GitHub Releases. Marketplace upload acceptance and update delivery still need to be checked. A subsequent version under the same extension ID should be used to verify editor update delivery and companion restart. [Microsoft publishing steps](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#publish-an-extension)

If Marketplace upload is blocked, keep the GitHub prerelease as the manual install channel and record the reported limit or error before changing packaging. Share a public link after verifying it from a fresh profile. Use GitHub Issues for ordinary feedback and the approved private contact for security reports.
