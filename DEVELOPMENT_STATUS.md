## Current implementation and open validation

- **Settings regression.** Reproduced the old tray callback in an isolated desktop. It opened a second native popup owned by the pet and created no Settings `BrowserWindow`. The replacement is a singleton with its own sandboxed local page, direct focus, independent saved bounds and off-screen recovery. The tested Windows build needed inactive show followed by focus to reveal a preloaded window reliably. Native smoke invoked the tray callback with the pet hidden and click-through enabled, rendered the Settings page, restored it from minimize, and saved an edit. The Windows computer-use helper could not connect to its native pipe, so physical tray and pointer actions remain manual QA.
- **Activity diagnosis.** **Live Codex quota** uses a separate quota-only process. Existing workspaces had no enrollment path in this build. UrTrades was outside the disposable probe, and its individual hook files, trust, and task were left alone. Settings now starts, checks and disconnects its disposable receiver. It distinguishes no setup, native review pending, observed work, no observable active sessions, stale and disconnected states. Matching files alone do not establish native trust. The native App Server saw eight untrusted hooks in each of two isolated workspaces and noticed independent removal. The synthetic smoke triggered model activity through generated commands while the pet was hidden, validated both workspace rows, and verified disconnect cleanup. Reload requirements and trusted native IDE delivery remain open.
- **Direct controls.** Dashboard and compact have settings, hide, top, animation, mode, refresh and options. Pet-only surfaces compact controls on hover and keeps the context menu and recovery routes. The native smoke exercised button actions with the shared tray state, valid preference edits, off-screen recovery and visibility. The live quota smoke passed independently over the documented interface; synthetic hook availability did not affect quota.

- **Window sizing.** Native Electron constraints reproduced the reported regression. A 356 × 368 window retained that minimum on a request for 264 × 300. Electron sets the maximum before the minimum on fixed-size windows. Pawmetry lowers the old floor before supplying smaller target bounds, then fits the selected preset to the monitor work area. Windows smoke verified both directions in all three visible modes, matching renderer dimensions, independent pet scaling, and a fresh Electron process restoring saved bounds and size. Mixed-DPI, drag, tray input and multi-monitor restart remain manual QA. [Electron native implementation](https://github.com/electron/electron/blob/v45.5.0/shell/browser/native_window_views.cc)
- **Activity.** The prior probe ran standalone, and the desktop always supplied unknown activity. It had no route from an external project and tool-only starts could miss a prompt without tool use. The opt-in desktop receiver now creates two logon-protected disposable folders and supports eight hooks, including `PreModelRequest` and `PostModelRequest`. The native App Server discovered those eight untrusted definitions in an isolated profile. A separate Windows smoke used generated commands to deliver sanitized synthetic inputs with the pet hidden, confirmed concurrent workspace state and renderer output, paused observation and resumed it. No provider turn, hook-trust change or existing project enrollment was made.
- **Activity claims.** Positive model/tool start, interrupt and session end evidence can yield working, interrupted and disconnected. Expired observations become stale. `Stop`, a model result, absent sources and unmapped projects remain unknown. The 15-second lease may expire during long silent work. VS Code's four-second poll can miss short observations. Native trusted delivery from the IDE, open-session continuity, concurrent live conversations and minimization remain pending.
- **Desktop and controls.** There are pet, compact, dashboard and hidden presentations, per-layout sizes, independent pet size and opacity, local settings, bounded in-window roaming and shortcut choices. The desktop and VS Code expose separate animation and monitoring controls. The Explorer view and palette use fixed authenticated operations. Launch the portable companion manually before reconnecting. IPC recovery passed automated tests. Independent Windows logon isolation and visual/input controls remain manual QA.
- **Quota and alerts.** One desktop scheduler still owns all reads. Quota access starts in simulation and live access is explicitly enabled. The workspace label and upstream data age remain unknown. Hidden mode keeps enabled monitoring active. Wake refresh respects the same rate limits and backoff. Quota alerts support per-event sound, quiet hours, thresholds and a test notification. Restoration requires fresh evidence for the same known account/quota scope. Task, approval and failure notifications are gated on authoritative evidence. Windows toast delivery, sound and sign-in startup are unverified. No startup registration was enabled during development.
- **Performance.** Five one-second hidden, offline samples on this workstation produced 0–0.16% aggregate CPU and about 349 MiB summed working set. Working sets can count shared pages more than once. This is a short Electron idle sample without provider reads or hook traffic.
- **Animation.** The atlas contract and synthetic metadata validator cover fixed rows, frame timing, anchors and left/right facing. The desktop retains the temporary CSS character. Artwork loading and visual inspection await approved assets. [Animation asset specification](ANIMATION_ASSET_SPEC.md)

The desktop smoke passed independent Settings, toolbar, renderer sizing, preference restart and synthetic activity checks. Direct live quota integration passed without starting an agent turn. The extracted portable ZIP and two isolated VSIX hosts passed. Updated local artifacts are in `dist/pawmetry-6mjo7w`.
